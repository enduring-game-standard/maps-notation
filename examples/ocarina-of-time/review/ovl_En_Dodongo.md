# ovl_En_Dodongo

Reviewer: Claude Sonnet 5.5 (claude-sonnet-5-5)

## Verdict

minor findings

## Findings

1. **Phase `stunned` (`frames` 80, cite 743) for reaction `0xF` (ARROW_ICE).** The ice case runs longer than 80 frames. `EnDodongo_SetupStunned` sets `iceTimer = 36` when `damageReaction == 0xF` (z_en_dodongo.c:420-422), and `EnDodongo_Draw` adds one to `actor.colorFilterTimer` every frame while `iceTimer != 0` (z_en_dodongo.c:945-948). `EnDodongo_Stunned` ends only when `colorFilterTimer == 0` (z_en_dodongo.c:723). An ice stun lasts about 80 + 36 = 116 frames (6 beats) against 80 (4 beats) for nut, boomerang and hookshot. Severity: minor (timing).
2. **Steps `walk -> idle` / `walk -> walk` (`range: 'far'`, `afterTimer`, cites 603 and 600).** The spec's `far` is "Link not within 100". In the code the walk timer runs only when Link is at least 400 from the Dodongo's home (`else` branch of the `< 400.0f` test, z_en_dodongo.c:581, 587-598). With Link between 100 and 400 from home the Dodongo keeps walking toward him (z_en_dodongo.c:582-583) and the timer does not tick. The spec lets it rest (70%) or re-walk (30%) whenever Link is far. Effect: in the model the Dodongo idles more often than the code allows while Link is in the middle band. Severity: minor (range/timing).
3. **Phases `hurt` and `sweep` (ledger key `EnDodongo_SweepTail`).** The ledger maps `EnDodongo_SweepTail` only to `hurt` (spec lines 76-86), but `sweep` is the same action function (the tail swing runs inside `EnDodongo_SweepTail`, z_en_dodongo.c:634-678). The C5 entry should name both. Severity: minor (labeling).
4. **Steps `hurt -> fire` / `hurt -> sweep` (cites 632, 647, no weight, no range).** The two steps tie as a coin flip. The code does not roll: it is decided by Link's facing relative to the Dodongo (`ABS(yawDiff1) < 0x4000` or `timer != 0` -> fire, else sweep, z_en_dodongo.c:624, 632, 634-647). Facing is not in the model, so the odds are not the code's. Severity: minor (labeling; unreported).
5. **Phases `idle`, `walk`, `fire`, `stunned` hits (armor not modeled).** The Dodongo has a hard-armor collider on the head that bounces weapons: `colliderHard`, `AC_HARD`, three tris (z_en_dodongo.c:150-197) accepting STICK, SLINGSHOT, EXPLOSIVE, ARROW, HAMMER_SWING, kokiri slash, kokiri spin, jump types and others (masks `0xF24BF96E` / `0xFFCBF96E`, z_en_dodongo.c:155, 166, 177). A bounce discards the body hit (z_en_dodongo.c:733-735), and the head sphere itself accepts only nut, boomerang, hookshot, master/giant sword types (`0x0D800691`, z_en_dodongo.c:128). Body spheres 0-2 accept every type (`0xFFCFFFFF`, z_en_dodongo.c:73, 84, 95), so Link can still hurt it with any weapon; the armor is positional. The spec does not mention it. Severity: minor (spatial, folded into "near", but not reported as a gap).
6. **Override `EXPLOSIVE` in `idle`, `idle_short`, `walk`, `fire_end`, `stunned` (`damage:0, to:'swallow'`, cite 806).** A bomb always becomes a swallow in these phases. In the code a swallow needs the bomb within |dx| < 20, |dy| < 10, |dz| < 20 of the mouth, with `params == 0` and no parent (z_en_dodongo.c:962-986, 806). A bomb that goes off elsewhere is a normal EXPLOSIVE hit for 2 damage with reaction 0 (table entry z_en_dodongo.c:223) and sends it to the damage branch (z_en_dodongo.c:752). The model removes that 2-damage route in five of the six hittable phases and makes the swallow certain. Severity: minor (the swallow is the intended play, but the damage route is lost and not noted).

## Outcomes

1. answered: the longer ice freeze is real (z_en_dodongo.c:421, 945-948, 723) but never survived. Reaction 0xF comes only from the ice arrow in play (ice magic is never emitted, studio/tools/ocarina/data/link.ts:96), and the ice arrow deals 4 (z_en_dodongo.c:232), the Dodongo's whole health (z_en_dodongo.c:337). The 0xF branch applies damage before the stun (z_en_dodongo.c:744-745), so the stun always ends in death (z_en_dodongo.c:724-725). A reaction already stunned ignores it (z_en_dodongo.c:742). No live phase runs 116 frames. A trial `stunned_ice` phase was unreachable in every kit, which confirms this. Reaction note updated to say so.
2. fixed, partly a gap: the far-band rest/wander steps (`walk -> idle` 603, `walk -> walk` 600) and the walk timer are removed. `far` now stands for the pursuit band (z_en_dodongo.c:581-585): a walking Dodongo with Link far holds and keeps walking toward him. The rest loop for Link 400+ from home (z_en_dodongo.c:587-604) is a third band the two-band model lacks; recorded in the spec header.
3. fixed: phases renamed `sweep_reel` and `sweep_tail`, and the C5 key is now `EnDodongo_SweepTail: 'sweep_*'`, so the ledger names both.
4. gap: the reel's exit is decided by Link's facing (z_en_dodongo.c:624, 634-647), which the model lacks. The two steps keep even odds; recorded in the spec header.
5. gap: the head armor (colliderHard, AC_HARD, z_en_dodongo.c:150-197) bounces hits by position and discards the body hit (z_en_dodongo.c:733-735). Position is not in the model, and the body spheres accept every type (z_en_dodongo.c:73, 84, 95), so every hit is taken on the body. Recorded in the spec header.
6. gap: a phase override is one outcome, so the bomb cannot be both a swallow (z_en_dodongo.c:962-986, 806) and a 2-damage reel hit (z_en_dodongo.c:223, 752). The swallow stays; the dropped 2-damage route is recorded in the spec header.
