# ovl_En_Rr

Reviewer: Claude Sonnet 5.5 (claude-sonnet-5-5)

## Verdict

minor findings

## Findings

1. **Step `approach_spat{,_fed}` (no step to `reach`).** The spec's spat phase has only a creep step and the timer exit. The code has no state for it: after the release the actor is in `EnRr_Approach` (z_en_rr.c:351), and `ocTimer = 110` (z_en_rr.c:316) only blocks the grab (z_en_rr.c:531). `EnRr_Approach` still runs its reach check, `actionTimer == 0 && xzDistToPlayer < 160` (z_en_rr.c:606-607), so a Like Like that has closed in during the lockout reaches, and a fed one then retreats (z_en_rr.c:266-268) before the lockout ends. The model instead sits in spat for the full 110 frames and reaches only afterward. Severity: minor (timing; the 110-frame no-grab window itself is right).

2. **Steps `damage* -> approach*` and `stunned* -> approach*`, entered from `approach_spat*`.** The `ocTimer` lockout keeps counting down through a wound (40 frames) or a stun (80 frames); it is not reset (`EnRr_SetupDamage`, z_en_rr.c:360-376, and `EnRr_SetupStunned`, z_en_rr.c:409-434, never touch `ocTimer`; it decrements at z_en_rr.c:805-807). A hit during spat leaves up to about 70 frames of no-grab after the wound ends (110 - 40; the allTo reactions at spec lines 118-127 send spat to damage). The spec returns to plain `approach`, where a swallow is possible at once. So the model can swallow Link earlier than the code. Severity: minor (timing).

3. **Phase `reach` frames (cite z_en_rr.c:242) and step `reach -> gape` (cite z_en_rr.c:640).** `reach` takes 20 frames for EXTEND only (z_en_rr.c:242). It then goes through STOP -> OPEN, 5 frames (z_en_rr.c:624), and OPEN -> GAPE, 2 frames (z_en_rr.c:631), before the 20-frame CLOSE (z_en_rr.c:638). Line 640 is the end of the gape (it sets `REACH_CLOSE`), not the start of the second phase. In beats the total is unchanged (27 frames and 20 frames both round to 1 beat), so this is a cite and label problem only. Severity: minor.

4. **`atSources` / ledger (unreported AC_HARD mouth).** `sCylinderInit2` (the mouth) is `AC_ON | AC_HARD` (z_en_rr.c:131). A hit that lands on it bounces: `if (collider2.base.acFlags & AC_HIT)` gives metal-shield sparks and no damage (z_en_rr.c:440-446). The spec's phases accept every damage type in every hittable phase and never mention the mouth bounce. It is a geometry matter the beat model cannot place, but the spec reports it nowhere. Severity: minor (unreported abstraction gap).

5. **Ledger `EnRr_GrabPlayer` exclusion reason.** The reason says "nothing else happens until the release steals and throws him (line 660)". The code has other exits from the hold. The hold also ends when Link breaks free: `!(player->stateFlags2 & PLAYER_STATE2_7)` (z_en_rr.c:659). A damaging hit while `hasPlayer` releases at once (z_en_rr.c:481-482), as does a stun expiring (z_en_rr.c:780-781). A hit that kills still throws him with the 8 damage and the theft first (z_en_rr.c:349, 353-357). The model has the hold last zero beats, so these paths cannot occur, and the exclusion is a fair abstraction, but the stated reason is not strictly true. Severity: minor (labeling).

## Checked

Giant's Knife, Giant spin, and Master jump are 4 (z_en_rr.c:157, 170, 174), which is its whole health, so the `miss_*_giant` dead-verb reasons hold. Giant jump is 8 (z_en_rr.c:173).
- Reactions: NORMAL, LIGHT/SHDW/WIND/SPRT arrows fall through to the NORMAL case (z_en_rr.c:459-471). NORMAL applies damage (z_en_rr.c:477), sets `invincibilityTimer = 40` and a 40-frame filter (z_en_rr.c:478-480), then `EnRr_SetupDamage` (z_en_rr.c:484), or the release if `hasPlayer` (z_en_rr.c:481-482). FIRE damages and stuns (z_en_rr.c:490-498); both fire rows are 4 (z_en_rr.c:158, 164), so it always kills. ICE and LIGHT_MAGIC damage and stun (z_en_rr.c:499-523). STUN is the boomerang and hookshot, 80 frames, no damage (z_en_rr.c:524-528; table rows at z_en_rr.c:151, 154). NONE matches no case (z_en_rr.c:458).
- Hittability: the `damage` phase takes no hits because `CollisionCheck_SetAC` is skipped while `invincibilityTimer != 0` (z_en_rr.c:832-834). `stunned` does take hits: the collision check is skipped only when the filter has the red flag `0x4000` (z_en_rr.c:817, `COLORFILTER_COLORFLAG_RED 0x4000` at include/actor.h:168), and stun uses BLUE (0x0000) or GRAY (0x8000) filters (z_en_rr.c:521, 526). So the spec's default `hittable` for stunned is right.
- Timers: damage 40 (z_en_rr.c:478), stunned 80 (z_en_rr.c:526), spat 110 (z_en_rr.c:316), `approach_wait` 60 (z_en_rr.c:270), retreat 100 (z_en_rr.c:267), gape/close 20 (z_en_rr.c:638). The unfed path `gape -> approach_wait` (z_en_rr.c:269-271) and the fed path `gape -> retreat` (z_en_rr.c:266-268) match. The `retreat -> approach` step with `retreat` cleared (z_en_rr.c:765-767) matches. `damage -> approach` (z_en_rr.c:672-673) and `stunned -> approach` (z_en_rr.c:778-783) match; the retreat flag survives both, which the `_fed` copies capture.
- Swallow: contact is gated by `ocTimer == 0`, `colorFilterTimer == 0`, and the player's `invincibilityTimer == 0` (z_en_rr.c:531-533), so no grab step from `damage`, `stunned`, or `approach_spat` is correct. Retreat is grabbable only when fed, which is right since `retreat` is true only after eating (z_en_rr.c:326, 333). Release throws with damage 8: `Actor_SetPlayerKnockbackLarge(..., 8)` (z_en_rr.c:349), and the knockback damage is added to the player's damage (z_player.c:4878). The 8 is the inventory's `directHurt` entry. 8 divides 32, so `link_hurt_overkill` is dead as stated.
- Theft: the shield is skipped only for the Mirror Shield (z_en_rr.c:322), the tunic only for Kokiri (z_en_rr.c:329). Both run in one call, so one contact takes both. `Inventory_DeleteEquipment` deletes any nonzero equip value (z_inventory.c:297-301), so the `EDIBLE` list of deku and hylian shields and goron and zora tunics is complete. A successful theft sets `retreat` (z_en_rr.c:326, 333); the unfed release goes straight to `EnRr_Approach` (z_en_rr.c:351).
- C5: the inventory lists 7 action functions (Approach, Damage, Death, GrabPlayer, Reach, Retreat, Stunned), and each is in `actionFuncs`. Death is a post-kill animation and drop (z_en_rr.c:685-740), and its entry points (z_en_rr.c:356, 487, 785) are defeats the pool already models.
- C6: the two AT-flagged elements (z_en_rr.c:118, 137) have base `AT_NONE` (z_en_rr.c:111, 130), and `grep SetAT` on the file returns nothing, so neither can strike. `swallow` is the only attack source (z_en_rr.c:349).
- Dead-verb reasons for kit splits: `adult_arrows` has the Mirror Shield and no non-Kokiri tunic (data/loadouts.ts:20), so its Like Like never eats. No kit with ice arrows or magic spins carries the boomerang or hookshot, so the `hit_*__stunned` reasons hold.
- The `adult_tunic` kit is needed: no standard kit wears a tunic other than Kokiri (data/loadouts.ts:9-22).

## Outcomes
1. fixed: `approach_spat*` now reaches when Link is near (`z_en_rr.c:606-607`). It goes to new `reach_spat*` and `gape_spat*` phases that cannot grab, then to `retreat` if fed (`z_en_rr.c:266-268`) or `approach_wait` if not (`z_en_rr.c:269-271`).
2. gap: the `ocTimer` lockout runs on its own clock through wounds, stuns and reaches (`z_en_rr.c:805-807`, never reset in `z_en_rr.c:360-376` or `z_en_rr.c:409-434`). The types tie a timer to one phase, so the model can grab up to about 3 beats early after a hit or a reach during the lockout. Recorded in the spec header.
3. fixed: the `reach` label now says it covers extend, open and gape. The header notes that the 20 frames are the EXTEND timer (`z_en_rr.c:242`), plus 5 and 2 more (`z_en_rr.c:624`, `z_en_rr.c:631`), which is still one beat. The step cite `z_en_rr.c:640` stays, because that line starts the 20-frame close that the `gape` phase models.
4. gap: the AC_HARD mouth bounce (`z_en_rr.c:131`, `z_en_rr.c:440-446`) depends on geometry. Recorded in the spec header.
5. fixed: the `EnRr_GrabPlayer` exclusion reason now lists every exit from the hold (`z_en_rr.c:659`, `z_en_rr.c:481-482`, `z_en_rr.c:780-781`, `z_en_rr.c:349`, `z_en_rr.c:353-357`).
