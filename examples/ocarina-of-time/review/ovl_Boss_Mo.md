# ovl_Boss_Mo

Reviewer: Claude Sonnet 5.5 (spec: `studio/tools/ocarina/data/actors/boss_mo.ts`; code: `src/overlays/actors/ovl_Boss_Mo/z_boss_mo.c`, `z_boss_mo_colchk.inc.c`; all lines below are in `z_boss_mo.c` unless a file is named)

## Verdict

major findings

## Findings

1. **major** - `attacks` / `steps` (tentacle contact outside `tent_strike`). The spec lets the tentacle hurt Link only through `lash` on the `tent_strike` -> `tent_held` step. The code sets the tentacle's AT collider (all 19 elements, damage 16, `AT_TYPE_ENEMY`) every update while the tentacle is drawn, its `INVINC_TIMER` is 0, its state is not GRAB or SHAKE, and `cutIndex == 0` (`z_boss_mo.c:2427-2433`). Element radius is nonzero for any state <= `MO_TENT_SHAKE` (`z_boss_mo.c:2446-2455`), so READY, SWING, ATTACK and CURL all hurt Link on contact. A hit in READY or SWING only sets `playerHitTimer` (`z_boss_mo.c:1217-1220`) and does nothing else, since only ATTACK and CURL read it (`z_boss_mo.c:681`, `z_boss_mo.c:747`). The result is 16 damage with no grab, from `tent_ready`, `tent_reset` and `tent_swing`, and the spec has no attack there. `atSources` maps all 19 `col()` lines to `lash`, which only fires in `tent_strike`.

2. **major** - `steps` (missing second tentacle). When the nucleus has taken 3 sword hits (`hitCount >= 3`, incremented at `z_boss_mo.c:1807`), a second tentacle spawns from tentacle 1's RETREAT case (`z_boss_mo.c:978-993`). From then on two tentacles act. The second one's ATTACK lasts 55 frames, not 175 (`z_boss_mo.c:657-661`). Each tentacle waits while the other holds Link (`HAS_LINK`, `z_boss_mo.c:647`, `z_boss_mo.c:686`, `z_boss_mo.c:706`). `tent_strike` is modeled with 175 frames only (`z_boss_mo.c:659`). The spec header and comments do not mention the second tentacle, so this is an unreported gap. After hit 3 the tentacle can strike roughly 3 times as often, which changes what hurts.

3. **major** - `attacks.lash.effect` (`damagePerBeat: 2`, 150 frames). The grab drain is `play->damagePlayer(play, -1)` once per 8 frames of the SHAKE timer (`z_boss_mo.c:815`). `damagePlayer` is `Player_InflictDamage` (`z_player.c:10715`), which calls `Health_ChangeBy` with -1 (`z_player.c:4598-4603`). That is 1 unit per 8 frames, or 2.5 per beat by the contract rule. Timer values 144, 136, ... 0 give 19 ticks while the 150 timer runs (more every frame once the timer is 0 and the exit test `z_boss_mo.c:850-852` has not yet passed). The spec gives 2 per beat over 8 beats, which is 16 units. The code gives about 19 or more. A -1 change is not halved by Double Defense (-1 >> 1 is -1), and the spec's `link_hurt_overkill` note matches that. The error is small, but it is a wrong quantity.

4. **minor** - `steps` `tent_strike` -> `tent_reset` (`far`, cite 698). In the same miss branch the code sends the tentacle to RETREAT with timer 75 when Link is more than 300 away in x or z, is below the water, or the other tentacle holds him (`z_boss_mo.c:706-710`). The spec has only the READY (30 frame) branch. Link standing far away sends the tentacle to `tent_retreat`, not `tent_reset`.

5. **minor** - `phases.tent_held` frames (150, cite 791) and the missing exit when the grab fails. `tent_held` also covers CURL (timer 40, `z_boss_mo.c:688-689`) and GRAB, which lasts until that timer reaches 0 (`z_boss_mo.c:781-787`). Link is pulled and frozen with no damage during that time (`z_boss_mo.c:775-780`). So the hold is about 40 frames longer than the 150 modeled. CURL can also end without a grab: `grabPlayer` fails (`z_boss_mo.c:753-761`), or the timer hits 4 (`z_boss_mo.c:764-772`). Both go back to READY with a 30 frame timer. The spec has no step from `tent_held` to `tent_reset`, so a lash always grabs in the model.

6. **minor** - `steps` `tent_cut` -> `tent_retreat` (`afterTimer`, cite 912), and `tent_cut` frames 40. The code leaves CUT when `meltIndex >= 41` or the timer ends (`z_boss_mo.c:910`). `meltIndex` rises 1 per frame from `cutIndex + 1` (`z_boss_mo.c:889-908`). Din's Fire sets `cutIndex = 15` (`z_boss_mo.c:1192-1196`), so the melt ends after about 25 frames (1 beat), not 40 (2 beats). A hookshot cut starts at the nucleus's position in the tentacle (`z_boss_mo.c:1835-1839`), so it is shorter for a deep nucleus.

7. **minor** - `phases.recover` (30 frames, cite 1980). STUNNED goes to MOVE with timer 30 when the stun timer ends (`z_boss_mo.c:1978-1981`). But if the nucleus is below the water line it goes to MAKE_TENT instead (`z_boss_mo.c:1982-1986`). From MAKE_TENT with the tentacle in WAIT the nucleus goes straight to MOVE with timer 70 (`z_boss_mo.c:1953-1957`). The sword stun knocks the nucleus back and it falls (`z_boss_mo.c:2080-2081`), so it often re-enters the water before the 25 frame timer ends. Recovery is then 70 frames (4 beats), not 30 (2 beats). I did not confirm that the nucleus is below the water line at the timer's end in typical play.

8. **minor** - `tentOverrides`, sword and hookshot damage 0 in the `SUBMERGED` phases (cite 2130) and in `tent_held` / `tent_cut` (cite 1796). For `tent_rise`, `tent_ready`, `tent_reset`, `tent_swing` and `tent_retreat`, the cite `z_boss_mo.c:2130` shows only that the nucleus sits 40 units under the tentacle base. The sword/hook gate in the code is state and `INVINC_TIMER` only (`z_boss_mo.c:1793-1796`, `z_boss_mo.c:1831-1833`). No depth or reach test is in the code, so "cannot be hit here" is a reach assumption, not a code rule. The spec should say so. For `tent_held`, the cite 1796 claims state >= ATTACK. But the core leaves ATTACK for RETREAT when the tentacle leaves ATTACK (`z_boss_mo.c:2002-2005`), and then goes to MAKE_TENT at `POS_IN_TENT <= 0` (`z_boss_mo.c:2009-2012`). Within `tent_held` the core is in a state < ATTACK, so line 1796 does not show the fact. Link cannot swing while held, so play is unaffected.

9. **minor** - `Attack.lash.blockable: false`. The tentacle AT flags are `0xFFCFFFFF` (`z_boss_mo_colchk.inc.c:5`) and the shield AC mask is `0xDFCFFFFF` (`z_player.c:10518`), so they share bits. The shield bounces a tentacle hit the same way it does the nucleus (`blockable: true`). The path that cancels damage on a bounce is `z_player.c:4882-4900`. `grabPlayer` (`func_80852F38`, `z_player.c:16089-16099`) does not check the shield, and a bounced AT still sets `ATELEM_HIT` (`z_collision_check.c:1720-1730`) and thus `playerHitTimer`. So a raised shield likely stops the 16 contact damage but not the grab. The spec treats them as one unblockable attack. I did not trace every player path to confirm how the bounced hit and the grab resolve together.

10. **minor** - `attacks.nucleus` / `steps` (nucleus bump only from `roam` and `recover`). The core cylinder's AT is set every update unless the core is STUNNED above water (`z_boss_mo.c:2279-2283`), so the nucleus also hurts Link (16 damage, `col(239)`) during MAKE_TENT, ATTACK and RETREAT, including while it rides inside the striking tentacle. The spec carries it from `roam` and `recover` only.

11. **minor** - `hookshot` in `tent_strike` (`damage.entries.HOOKSHOT.to: stunned_hook`, cite 1847). With the core in ATTACK or RETREAT (state >= ATTACK), a hookshot hit also cuts the tentacle: tentacle 1 goes to CUT with timer 40 and Link is released (`z_boss_mo.c:1833-1846`). The spec only stuns the nucleus, so the tentacle then restarts from `tent_rise`. In the code the tentacle goes CUT, RETREAT, DESPAWN, WAIT first, and the core waits for it to be WAIT or READY before raising another (`z_boss_mo.c:1939-1941`). The tentacle is away much longer than the model shows.

12. **minor** - `states.MO_CORE_RETREAT` -> `tent_retreat`, and `states.MO_CORE_ATTACK` -> `tent_strike` (cites 2008, 1993). The core enters RETREAT whenever the tentacle leaves ATTACK or CUT (`z_boss_mo.c:2002-2005`), which includes the start of `tent_held` and `tent_reset` (and Din's Fire on the nucleus, `z_boss_mo.c:1789-1791`), not only `tent_retreat`. It enters ATTACK from a cut tentacle too (`z_boss_mo.c:1958-1962`), which is `tent_cut`, not `tent_strike`. Neither mapping is a combat error, because both states block sword damage the same way. Both are mislabeled.

## Checked

- Recover to tentacle: `z_boss_mo.c:1944-1947` (MAKE_TENT, tentacle SPAWN, timer 70); roam timer 70 at `z_boss_mo.c:1956`; tent_ready 60 at `z_boss_mo.c:578-579`; tent_swing 50 at `z_boss_mo.c:648-649`; strike 175 for tentacle 1 at `z_boss_mo.c:657-661`; retreat 75 at `z_boss_mo.c:865`, `z_boss_mo.c:913`; reset 30 at `z_boss_mo.c:698-704`.
- Din's Fire cuts the tentacle through its AC (`z_boss_mo.c:1191-1196`), timer 40 at `z_boss_mo.c:1196`.
- Attack damage: all 19 tentacle elements and the nucleus cylinder (`z_boss_mo_colchk.inc.c:239`) have `atDamage` 16 (`0x10`) and no special effect; the inventory agrees.
- `z_boss_mo.c:861` knockback has damage argument 0, so the exclusion's reason is true; `z_boss_mo.c:815` is the only damaging direct hurt call.
- State exclusions: `MO_CORE_UNUSED` is only in the enum (`z_boss_mo.c:131`) and the empty case (`z_boss_mo.c:1988`), so "no code sets this state" is true. The intro states (`z_boss_mo.c:1904`, `z_boss_mo.c:2018`) and the death states (`z_boss_mo.c:1019-1148`) belong to cutscenes. `MO_CORE_UNDERWATER` (`z_boss_mo.c:1929-1935`) is reached only when Link is more than 50 units under water.

- `atSources`: 19 tentacle elements at `col(7 + 11k)` plus `col(239)` equal the inventory's 20 elements; `at(861)` excluded as above.

## Outcomes
1. fixed: new attack `tent_contact` (16, none, blockable, source `col(7)`) on near self-steps in `tent_ready`, `tent_reset`, `tent_swing` (cite `z_boss_mo.c:2432`). READY/SWING are states 0/1, so radius is live (`z_boss_mo.c:110-117`, `2450`); SPAWN (11) and RETREAT (101) get radius 0, so `tent_rise` and `tent_retreat` carry no contact.
2. gap: an encounter is one actor, and no pool threshold counts hits (`hitCount`, `z_boss_mo.c:1807`) instead of health. Recorded in the spec header with `z_boss_mo.c:978-994`, `657-662`, `647`, `686`, `706`.
3. fixed: `damagePerBeat: { value: { units: 1, frames: 8 }, cite: z_boss_mo.c:814 }`, which is 5 every 2 beats, or 20 over the 8-beat grab. The frame-by-frame drain after the timer hits 0 (`z_boss_mo.c:850-853`), and Double Defense not halving -1 (the generator halves it), are recorded in the header as gaps.
4. gap: the range bands cannot tell the 300-unit RETREAT test (`z_boss_mo.c:705-711`) from the 120-unit grab test (`z_boss_mo.c:686`). Recorded in the header. The miss still goes to `tent_reset`.
5. gap: a grab has one duration and a phase has one timer, so the 40 frames of CURL/GRAB with no drain (`z_boss_mo.c:689`, `775-787`) are not added. The grabPlayer refusal (`z_player.c:16090-16091`) depends on player states the model lacks. Both are recorded in the header. The timer==4 return (`z_boss_mo.c:764-772`) needs a strike that never touched Link, and in the model that is the far miss to `tent_reset`.
6. fixed: `tent_cut` frames 25, cite `z_boss_mo.c:911`. Din's sets cutIndex 15 (`1193`), and the melt runs to 41. Hookshot cuts now go to a separate path (see 11).
7. gap: the branch depends on the nucleus's height, which the model does not track. Recorded in the header with `z_boss_mo.c:1982-1986`, `1953-1956`. The 30-frame recovery is kept.
8. fixed: the reach judgment is now stated in the header (`z_boss_mo.c:2130`, `1793-1796`, `1831-1833`). The `tent_held` sword/hookshot cites now point to `z_player.c:16093` (Link is put in the held action), not `1796`.
9. holds in part, kept as a gap: the shield bounces the 16 contact (`z_player.c:4882`), but `z_collision_check.c:1730` still sets ATELEM_HIT, so `z_boss_mo.c:1217-1219` sets playerHitTimer, and grabPlayer (`z_player.c:16089-16099`) still grabs. One attack has one `blockable`, so the lash stays unblockable (the grab is the larger cost). The overcharge is recorded in the header. The new `tent_contact` is blockable.
10. fixed in part: near nucleus self-steps added in `tent_cut` (the core is in ATTACK riding the melting tentacle, `z_boss_mo.c:1958-1959`, AT at `2280`) and in the new `recover_cut`. Left out under the tentacle base (MAKE_TENT, 40 units under it, `z_boss_mo.c:2130`) on the same reach judgment as 8, which is recorded in the header. Left out in `tent_held`, because Link is held at the tip while the core retreats to the base (`z_boss_mo.c:2009-2012`). In `tent_strike` the lash already covers contact.
11. fixed: in `tent_strike` and `tent_cut` (core state ATTACK), a hookshot hit now goes to the new `stunned_hook_cut` phase (30 frames, `z_boss_mo.c:1838`, `1848`). Then it goes to the new `recover_cut` phase (75 frames, the tentacle RETREAT timer `z_boss_mo.c:913`, where the core waits for WAIT/READY per `1939-1941`), and then to `tent_rise`. Not modeled: DESPAWN's extra (Rand 20)+30 frames (`z_boss_mo.c:973`).
12. fixed: `MO_CORE_ATTACK` and `MO_CORE_RETREAT` now map to `tent_*`.

Coordinator note on the fixer's harness gap "the generator halves the grab drain under Double Defense": checked, it does not. `grab_costs` gives 5 `link_dmg` (encounters/boss_mo.maps:1743-1748) and `link_hurt` drains it with no Double Defense gate (boss_mo.maps:336-337). That matches the code, where `-1 >> 1` stays -1 (src/code/z_parameter.c:2252).
