# ovl_En_Fd

Reviewer: Claude Sonnet 5.5 (claude-sonnet-5-5)

## Verdict

major findings

## Findings

1. **Pools `core1`, `core2`, `core3` and step `core_r -> rise_r` (cite 669); pool `hp.cite` 247.** The spec keeps one 8-health pool per round, so damage dealt to a core that escapes carries over to the next time the fire form is exposed in the same round. The code makes a fresh core each time: `EnFd_SpawnCore` sets the new core's health to `fire form health % 8`, or 8 when that is 0 (z_en_fd.c:244-248). The fire form's health stays 24, 16 or 8 (all multiples of 8) until a core is emptied (z_en_fw.c:164-170), so every new core starts at 8. The old core is killed when it gets home (z_en_fw.c:367-370). Core damage that does not empty it is lost. In the model Link can chip a core down to, say, 2 over three exposures; in the code he must deal 8 inside one core window. The generator keeps pool state across phases (gen.ts:358-363, 416-423, no reset). Severity: major (changes how much Link must do and which strategies win).
2. **Phases `jump_r` and `land_r` have no attack (steps `jump_r -> land_r` cite 532, `rise_r -> jump_r` cite 518).** The body AT is set in every action function except `Reappear`, `SpinAndGrow` and `WaitForCore`: `if (actionFunc != Reappear && != SpinAndGrow && != WaitForCore) { if (attackTimer == 0 && invincibilityTimer == 0) CollisionCheck_SetAT(...)` (z_en_fd.c:708-712). So `EnFd_JumpToGround` and `EnFd_Land` are armed: the leap and the get-up can burn Link for 4 (z_en_fd.c:72), with knockback (z_en_fd.c:321-333). The spec attaches `flame_body` only to `spin_r` and `run_r`, so Link is safe from the dancer during `jump` and `land`, where the code can hurt him. Severity: major (what can hurt Link, by phase).
3. **Phase `run_r` (`frames` [30,149], cite 592) and step `run_r -> jump_r` (afterTimer, cite 616).** The run lasts much longer than the 30-149 frame `spinTimer`. `EnFd_ShouldStopRunning` returns false while `circlesToComplete != 0`, and `DECR(spinTimer)` is evaluated only after that (z_en_fd.c:451-453, short-circuit `||`). `circlesToComplete` is set to `(frames & 7) + 2`, so 2-9 circles (z_en_fd.c:591), and `spinTimer` then counts down from 30-149 (z_en_fd.c:592). The run therefore lasts the circles plus the timer: with radius about 200 at speed 8 (z_en_fd.c:641, 651) one circle is about 150 frames, so roughly 340-1500 frames, not 4 beats. The run also ends immediately on a wall hit in the next step of the circle (z_en_fd.c:445-449, then jump at 612-616), which the spec does not carry. Severity: minor (timing; order-of-magnitude difference, so the exposure rate in the model is too high).
4. **Attack `flame_body` in `spin_r` (cite 711) and `run_r` (cite 639): no cooldown.** After a contact the dancer sets `attackTimer = 30` (z_en_fd.c:330), and `SetAT` is skipped while it is nonzero (z_en_fd.c:710-711); `EnFd_FindPotentialTheat` also ignores Link then (z_en_fd.c:402-404). The model allows a hit every beat (20 frames); the code allows at most one per 30 frames. Severity: minor (timing).
5. **Phase `core_r` hittable set.** The core is not hittable all the time it exists. After spawning it bounces three times in `EnFw_Bounce` with no AC set (z_en_fw.c:224-229, AC only in `EnFw_Run` at z_en_fw.c:385-387); AC is also off for `damageTimer` (20 frames) after each hit (z_en_fw.c:253, 385) and during `explosionTimer`. The spec has the core hittable every beat. Severity: minor (timing).

## Outcomes
1. fixed: step `core_r -> rise_r` now carries `restore: { pool: core_r, to: 8, cite: z_en_fd.c:247 }`, so damage to a core that escapes is lost and every exposure needs 8 inside one core window. The three `coreN_stands_again` verbs are ledgered: the restore fires only on the step home, and an emptied core leaves by the pool's `then`. ovl_En_Fw already models one core's life from 8, so it needed no change.
2. fixed: `jump_r -> land_r` and `land_r -> spin_r` are now split into a far step and a near step that delivers `flame_body` (AT registered outside Reappear/SpinAndGrow/WaitForCore, z_en_fd.c:708-712).
3. gap: the circles part of the run (2-9 circles, z_en_fd.c:591, checked before `spinTimer` at 451) has no frame count in code; a circle's length follows Link's distance from home (z_en_fd.c:629-636). The wall-hit exit (z_en_fd.c:445-449) is room geometry. The run keeps the cited 30-149 timer as a lower bound. Recorded in the spec header.
4. gap: the 30-frame `attackTimer` (z_en_fd.c:330, 710) runs alongside the spin/run timers, and a phase has one timer. Recorded in the spec header.
5. fixed (partly): a new `bounce_r` phase (hittable none, z_en_fw.c:225-227) now sits between exposure and `core_r`, and the core's return timer starts after it, as at z_en_fw.c:226. gap: the per-hit AC cooldown (damageTimer 20 after landing, z_en_fw.c:253, 284-290) runs alongside the return timer and is not modeled. Recorded in the spec header. `explosionTimer` is set only on the finishing blow (z_en_fw.c:256), after the encounter ends.
