# ovl_Boss_Va

Reviewer: Claude Sonnet 5.5 (spec: `studio/tools/ocarina/data/actors/boss_va.ts`; code: `src/overlays/actors/ovl_Boss_Va/z_boss_va.c`; all lines below are in `z_boss_va.c` unless a file is named)

## Verdict

major findings

## Findings

1. **major** - `pools` `round_2` / `round_3` (3 health each, cite 1414). The spec starts each round with fresh health. The code keeps one counter, `sPhase4HP`, and refills it with `sPhase4HP += 3` after it reaches 0 or below (`z_boss_va.c:1410-1414`). The counter is an `s8` (`z_boss_va.c:419`), so overkill carries into the next round. With 2-damage hits (Deku Stick, Kokiri jump slash, per the table at `z_boss_va.c:370`, `z_boss_va.c:391`) the code takes round 1: 4 -> 2 -> 0, refill to 3; round 2: 3 -> 1 -> -1, refill to 2; round 3: 2 -> 0, dead. That is 2 + 2 + 1 = 5 hits. The spec needs ceil(3/2) = 2 hits in round 3, so 6 hits. With 1-damage hits the two agree (4, 3, 3). Larger hits carry more. The spec's `pools` have no way to carry a remainder, and the author did not report the gap.

2. **major** - `phases.p3_stun_*` / `steps` (no zapper step). The spec gives `p3_stun_n` only `touch`. In the code a zapper fires in `BossVa_ZapperAttack` when the body's `speed == 0` (`z_boss_va.c:2028-2031`), `sBodyState & 0x80` is clear (`z_boss_va.c:2036`), and Link is not mid-hit. During the phase 3 stun the body's speed is smoothed to 0 (`z_boss_va.c:1299`), the `ZapperHold` exit fires at speed 0 (`z_boss_va.c:2416-2418`), and `sBodyState` is 0 (`z_boss_va.c:1284`) until the timer falls under 35 (`z_boss_va.c:1295-1296`). So lightning (4 damage, unblockable, `z_boss_va.c:314`) can fire for roughly the first 100 of the 131 stun frames. The spec gives Link a stun phase with no lightning. This is the window in which he stands to hit the Bari. Moderate confidence on the exact window; the missing hurt source is certain from the lines cited.

3. **minor** - `steps` `p3_act_*` (zapper steps with no condition). The code holds the zappers while the body moves: `ZapperAttack` goes to `ZapperHold` whenever `speed != 0` in phases below 4 (`z_boss_va.c:2028-2031`), and the roaming body runs at speed 3.0 (`z_boss_va.c:1290`). Zappers fire in `p3_act` only while some Bari holds `sPhase3StopMoving` (the 128 of every 512 `timer2` frames with `timer2 & 0x1FF < 128`: `z_boss_va.c:2612-2618`, `z_boss_va.c:1314-1316`, `timer2++` at `z_boss_va.c:2868`). The spec lets a zapper fire any beat of `p3_act`, at equal odds with the other steps. This overstates lightning in `p3_act` and understates it in `p3_stun` (finding 2).

4. **minor** - `reactions['0x1']` (`to: stunTo`) and `phases.p4_stun_*`. The reaction maps only `p4_roam_k` to `p4_stun_k`. `p4_stun_k` lists `BOOMERANG` among its hittable types (it is in `BODY_OPEN`, `z_boss_va.c:1464`), but the spec gives that hit no effect. In the code a boomerang hit on the stunned core (`timer >= 0`, `invincibilityTimer == 0`) takes the reaction-1 branch again and resets the stun to 160 +/- 20 frames (`z_boss_va.c:1403-1406`, `z_boss_va.c:1423-1428`). So a boomerang can hold the core open. The model's stun always runs its timer out.

5. **minor** - `actionFuncs` mapping. `BossVa_ZapperAttack` and `BossVa_ZapperDamaged` map to `p1_*` only, and `BossVa_ZapperHold` to `p2_move_*` only. The code runs `ZapperAttack` in phases 1, 2 (pause), 3 and as the exit of `ZapperDamaged` (`z_boss_va.c:2164-2169`), runs `ZapperDamaged` whenever `sBodyState & 0x7F` is set in any phase (`z_boss_va.c:2023-2026`, `z_boss_va.c:2289-2292`), and runs `ZapperHold` in phase 3 as well (`z_boss_va.c:2028`). The spec's own steps put zapper lightning in `p2_pause`, `p3_act` and `p4_*`, which the ledger does not list. The behavior is spread over phases, so the glob cannot express it, but the ledger label is wrong.

6. **minor** - `phases.p2_move_n` / `p2_pause_n` (256 frames each, cite 1215). The body's own contact adds to the timer: `sPhase2Timer = (sPhase2Timer + 0x18) & 0xFFF0` on every AT hit (`z_boss_va.c:1192`). A touch therefore shifts the sway/pause cycle by 24 frames and clears the low 4 bits. A boomerang stun also clears the timer's low 9 bits (`z_boss_va.c:1169`), which the spec does model as the stun -> move step. The AT-hit shift is not modeled or reported. Timing only.

## Outcomes
1. fixed: the three round pools are now one `core` pool of 13 (4 at `z_boss_va.c:1372` plus the three `+= 3` refills at `z_boss_va.c:1414`), with thresholds at 9 and 6 that end rounds 1 and 2 (`z_boss_va.c:1411`) and one at 3 that defeats it (`z_boss_va.c:1415`). Damage drains one band after another, so overkill carries over exactly as the s8 counter does. The analysis reaches round 2 starting at 2 and round 3 starting at 2 and at 1. One case is left as a gap in the spec header: the child's 4-damage Deku Stick jump (`z_boss_va.c:393`) landing on round 2's last point leaves the code needing one more hit in round 3, and the model ends the fight on round 3's stun.
2. fixed: `p3_stun_*` now has the zapper steps. Gap: the code stops the zappers once the stun timer falls under 35 (`z_boss_va.c:1295-1296`, `z_boss_va.c:2036`), and the model keeps lightning possible for the whole 131 frames. Recorded in the spec header.
3. fixed: `p3_act_*` is split into `p3_act_move_*` (384 frames, `z_boss_va.c:2612`; zappers hold, `z_boss_va.c:2029`) and `p3_act_halt_*` (128 frames, `z_boss_va.c:2617`; body stopped, `z_boss_va.c:1315`; zappers fire). The Bari timer starts at 0x80 on entry and on rejoin (`z_boss_va.c:2551`, `z_boss_va.c:2792`), so every stun returns to `p3_act_move_*`.
4. fixed: a boomerang on the open core now restarts the stun. `p4_stun_k` and a new `p4_restun_k` alternate on reaction 0x1 (`z_boss_va.c:1424`), so each re-stun starts a fresh 140-180 frame timer. The old `p4_stun_3_timer_clears` ledger entry was dropped because that verb is now reachable.
5. fixed in part: `BossVa_ZapperDamaged` now maps to `p*`. Gap: C5 takes one glob per function, so `BossVa_ZapperAttack` stays on `p1_*` and `BossVa_ZapperHold` on `p2_move_*`. The spec header lists every phase each one runs in (`z_boss_va.c:2028-2031`, `z_boss_va.c:2416-2418`).
6. gap: a body touch moves `sPhase2Timer` on by 24 frames (`z_boss_va.c:1192`), and a step cannot shorten a phase timer. Recorded in the spec header.
