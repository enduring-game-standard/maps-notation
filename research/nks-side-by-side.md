# How NKS makes rule families comparable at a glance

Research for [issue #6](https://github.com/enduring-game-standard/maps-notation/issues/6). The question: how does Wolfram's *A New Kind of Science* (NKS) draw families of rules so that their differences show at a glance, and what does that mean for MAPS layout and visuals ([map: #3](https://github.com/enduring-game-standard/maps-notation/issues/3))?

Sources are the NKS online edition (wolframscience.com/nks, main text, notes, and page images), the Wolfram Physics Project technical introduction (PDF), Wolfram's writings, and the SetReplace source code. Page numbers are NKS print pages.

## Summary: what bears on MAPS

1. **NKS compares behavior, not rule diagrams.** The famous side-by-side pages (pp. 55-56) show what each rule *does* under one fixed protocol: same start (one black cell), same length (30 steps), same frame, same scale. The rule itself shows up only as a number under each picture. For MAPS, the closest thing is the reachability graph the studio already computes, not the hand-laid net. Wolfram has drawn exactly this for tic-tac-toe: a 5,478-node multiway graph, the same position count the MAPS analyzer reports.
2. **A rule picture is a fixed template where only the outputs change.** Every elementary rule icon has the same eight slots in the same order (111 to 000, left to right), and only the bottom cell of each slot varies (p. 53). You compare two rules by looking at the same slot in both. A MAPS verb glyph could work the same way: fixed slot positions for take, need, unless, and give, with the same glyph for each arc kind every time.
3. **Identity is canonical and does not depend on layout.** Each rule gets one number, computed from its outputs. Equivalences (left-right mirror, black-white swap) reduce the 256 rules to 88 classes. The Physics Project extends this to graph rules: a canonical form that ignores how elements are named, a "signature" that keys the family, and registry "short codes" for notable rules. Both Wolfram texts say plainly that node positions in a graph picture have "no fundamental significance." **This conflicts with SPEC.md**, which makes `at x y` part of the design. MAPS may need two things kept separate: a canonical identity that ignores layout, and an authored layout that is presentation.
4. **To compare graphs, Wolfram drops free layout and uses a uniform one.** For network systems he puts all nodes on a line, one connection kind above and the other below. He says this "obscure[s] the geometrical structure" but "more readily allows comparison between different networks" (pp. 197-198). He also shows one network looking different under two layouts (p. 196). Multiway and causal graphs are layered so each row is a step or a moment in time (pp. 205-209, 490). For MAPS this means a layout that is either algorithmic or tied to a protocol, used whenever two designs are compared, even if authoring stays hand-placed.
5. **Black and white on purpose.** NKS avoids color because color perception depends on surroundings and "make[s] all sorts of spurious patterns appear" ("Using color" note). The Physics Project does use color, but one shared style table fixes it for every picture of a given kind. MAPS seat colors carry meaning, so they should come from one fixed palette with one meaning each. Anything a reader must compare across designs should not rely on hue alone.
6. **Grid order lines up with structure, and invariants sit beside the pictures.** The 256-rule pages run in numeric order, 8 per row, so each column shares the outputs for the three lowest neighborhoods. Multiway pages plot state counts per step as small, matching charts next to the graphs (p. 205). The Physics Project compares graph invariants (node and edge counts) to get around layout arbitrariness. For MAPS, the analyzer's counts (positions, endings, plays, max marks per state) are the obvious figures to print beside each picture.
7. **Method: enumerate mindlessly, look at raw pictures, make rendering parametric.** Wolfram credits the rule 30 discovery to finally printing "straightforward pages of pictures of all 256 elementary rules." He prefers "a mindless search of a large number of possible cases" and warns against working from summaries (pp. 111-112). His picture programs were "general enough" to regenerate any figure with different steps or sizes ("Pictures in the book" note).

## Detail

### 1. Canonical rule icon (elementary cellular automata)

- p. 24 sets the format: "The top row in each box gives one of the possible combinations of colors for a cell and its immediate neighbors. The bottom row then specifies what color the center cell should be on the next step." https://www.wolframscience.com/nks/p24--how-do-simple-programs-behave/
- p. 53: "The overall structure of these rules is the same in each case; what differs is the specific choice of new colors for each possible combination." The rule number "when written in base 2, it gives a sequence of 0's and 1's that correspond to the sequence of new colors chosen for each of the eight possible cases." https://www.wolframscience.com/nks/p53--more-cellular-automata/
- I checked the inline images (`/nks/img/inline/page0053a.png`, `page0053b.png`). The eight boxes always run 111, 110, 101, 100, 011, 010, 001, 000 from left to right. The output bits under them read as the binary rule number, most significant bit first, with the 0 = 0, 1 = 1, 2 = 2, ... 255 = 255 ladder drawn out. Every icon is framed the same way and labeled "rule N" in italics underneath.
- History: the numbering comes from Wolfram's 1983 paper. He called two-color nearest-neighbor rules "elementary" because their rules are "as simple as possible." https://www.wolframscience.com/nks/notes-3-2--history-of-numbering-scheme/
- Other families get matching templates and numbers. Three-color totalistic rules get a base-3 "code number," with the rightmost slot for average color 0 (p. 60, https://www.wolframscience.com/nks/p60--more-cellular-automata/). Mobile automata are enumerated as 65,536 rules (p. 71). Two-state, two-color Turing machines are enumerated as 4,096 rules, and their rule icons sit in a legend keyed (a) to (f) to the pictures (p. 79, page image inspected).

### 2. Side-by-side layout: the 256-rule pages

- Caption, pp. 55-56: "The behavior of all 256 possible cellular automata with rules involving two colors and nearest neighbors. In each case, thirty steps of evolution are shown, starting from a single black cell." https://www.wolframscience.com/nks/p55--more-cellular-automata/
- From the p. 55 page image (`/nks/pages/p55--more-cellular-automata/image-large.png`): an 8 by 16 grid holding rules 0 to 127 in ascending order, left to right and top to bottom, with rules 128 to 255 on p. 56. Every cell has the same frame, aspect, and size, with only "rule N" beneath it. No rule icon appears in the grid; the number is the key back to the p. 53 icon. Because each row holds 8 rules, every column shares the lowest 3 bits, which are the outputs for neighborhoods 010, 001, and 000. You can see this on the page: columns 2, 4, 6, and 8 (the odd rules, where 000 maps to black) all show striped, flashing backgrounds. That reading is my own observation from the image. NKS does not state it as a design reason.
- Same scale, stated outright on p. 52: "Note that all the pictures are shown on the same scale; the last picture appears coarser because the structures it contains are larger." https://www.wolframscience.com/nks/p52--the-search-for-general-features/
- Fixed cell size beats fixed frame. On p. 79 the Turing machine panels all share a height (same step count), but their widths vary with how far each pattern spreads. My reading of the image is that the cell size stays fixed and the frame adapts to it. NKS does not state this as a rule.
- Ordering barely matters for what you see: "The fact that successive rules often show very different behavior does not appear to be affected by using alternative orderings such as Gray code." https://www.wolframscience.com/nks/notes-3-2--rule-orderings-for-cellular-automata/
- Equivalences: "some of the rules are related just by interchange of left and right or black and white (e.g. rules 2 and 16 or rules 126 and 129). There are 88 fundamentally inequivalent such elementary rules" (p. 56 caption). The note gives the table and the operations: `1 - Reverse[list]` and the permutation `{1,5,3,7,2,6,4,8}`. The smallest number in each class is printed in bold. https://www.wolframscience.com/nks/notes-3-2--rule-equivalences-for-cellular-automata/
- Degenerate rules get named: 51 is complement, 170 left shift, 204 identity, and 240 right shift. https://www.wolframscience.com/nks/notes-3-2--special-cellular-automaton-rules/

### 3. Graph systems: networks, multiway systems, causal networks (graph-not-grid prior art)

- Layout carries no meaning: "to make a picture of a network system, one has to choose particular positions for each of its nodes. But the crucial point is that these positions have no fundamental significance: they are introduced solely for the purpose of visual representation" (p. 193). https://www.wolframscience.com/nks/p193--network-systems/
- Free layout misleads: "networks (a) and (c) are identical, though they look different because the nodes are laid out differently on the page" (p. 196). https://www.wolframscience.com/nks/p196--network-systems/
- A uniform layout for comparison: "one must first find a uniform way of displaying the networks ... based on always arranging the nodes in each network in a line across the page. And although this representation can obscure the geometrical structure of a particular network ... it more readily allows comparison between different networks. ... one connection is therefore always shown going above the line of nodes, while the other is always shown going below" (pp. 197-198). https://www.wolframscience.com/nks/p198--network-systems/ The p. 199 image shows four rules side by side in equal-height frames, with successive steps on successive lines down the page.
- Multiway systems (pp. 204-209). Each state is drawn as its actual content (its row of cells), not as a label. Steps run down the page. Each panel has its rule icon framed in an inset at the top right, and the panels are (a) and (b) at equal height, followed by matching small plots of "the total number of possible states obtained at each step, and the differences" (p. 205 image). On p. 208, each sequence is "shown explicitly only once, and any sequence generated more than once indicated just by an arrow going back to its first occurrence." p. 209 then drops the layered picture for "the network of what sequence leads to what other" and shows it in eight panels of the same size, steps 1 to 8. In the image, nodes seem to keep their positions from one stage to the next; I did not confirm that against the source program. https://www.wolframscience.com/nks/p208--multiway-systems/ and https://www.wolframscience.com/nks/p209--multiway-systems/
- Games as networks: "One can think of positions or configurations in a game as corresponding to nodes in a large network, and the possible moves in the game as corresponding to connections between nodes. ... even the network for tic-tac-toe, for example, has 5478 nodes." https://www.wolframscience.com/nks/notes-5-6--game-systems/
- Causal networks are laid out by time: the networks "were specifically laid out so that successive rows of nodes going down the page wou[ld]" correspond to successive moments (p. 490, extract truncated at that point). pp. 488-489 build the causal network from a mobile automaton picture in panels (a) to (i), changing one thing per panel. https://www.wolframscience.com/nks/p490--time-and-causal-networks/

### 4. Wolfram Physics Project

Technical introduction, "A Class of Models with the Potential to Represent Fundamental Physics" (PDF: https://www.wolframphysics.org/technical-introduction/inc/Wolfram-ModelsForPhysics.pdf; HTML: https://www.wolframphysics.org/technical-introduction/).

- **Signature as the family key.** "the 'signature' of a rule, defined as the number of relations of each arity that appear on the left and right of each transformation". For example, `{{x,y},{x,z}} → {{x,y},{x,w},{y,w},{z,w}}` has signature 2₂ → 4₂. Families are then studied signature by signature: "There are 4702 distinct left-connected rules with this signature [2₂ → 3₂]. Here is a random sample of the behavior they generate, starting from a double self-loop {{0,0},{0,0}} and run for 8 steps."
- **Canonical form.** Rules are written in "a particular canonical form obtained by permuting names of elements and orders of relations in all possible ways, numbering elements starting at 1, and using the lexicographically first form obtained." Deciding whether two rules are equivalent "is essentially a problem of hypergraph isomorphism." A rule can be turned into an integer through a tupling function, but "unlike for systems like cellular automata ... only a small fraction of integers constructed like this represent inequivalent rules." So notable rules get "short codes" (e.g. `wm8678`) from hashing the canonical form, with "a central repository to ensure that short codes remain unique" (the Registry of Notable Universes).
- **Layout arbitrariness, stated twice.** "the detailed visual layout of graphs can affect the impression of these structures". And later: "there is considerable arbitrariness in the way we choose to present or visualize graphs ... to avoid the arbitrariness of different graph or hypergraph presentations, we can look at graph or hypergraph invariants," starting with node and edge counts.
- **States graph.** Following NKS p. 209, "we only ever keep one connection between any given pair of states." For causal graphs: "for visualization purposes, it is usually useful to use an updating scheme where as much happens as possible at each step." The text often switches between a "layered rendering" and an alternative rendering of the same graph.
- **The reproducible sample grid.** The 2020 announcement post publishes the code behind its grid of rule outputs: seeded `RandomSample`, fixed initial state `{{0,0},{0,0}}`, 8 steps, `GraphLayout -> "SpringElectricalEmbedding"`, a filter of `EdgeCount > 10 && ConnectedGraphQ`, and 60 results in a 10-column `GraphicsGrid`. The same post shows one grid graph "with exactly the same connectivity structure—rendered four different ways," and says "the actual layout on the page is just a choice made for visual presentation." https://writings.stephenwolfram.com/2020/04/finally-we-may-have-a-path-to-the-fundamental-theory-of-physics-and-its-beautiful/
- **One style table for all pictures.** `WolframPhysicsProjectStyleData` (https://resources.wolframcloud.com/FunctionRepository/resources/WolframPhysicsProjectStyleData/, v8.1.0, 2022-11-04) "yields an association describing default styles used in the Wolfram Physics Project." It covers each plot kind: StatesGraph, CausalGraph, EvolutionCausalGraph, BranchialGraph, SpatialGraph, Rule, and others. The open-source values live in SetReplace `Kernel/A0$style.m` (https://github.com/maxitg/SetReplace/blob/44c868bf4622e4542b306846ffdcc47c19d0bba8/Kernel/A0%24style.m). A few examples: event vertices `Hue[0.11, 1, 0.97]` (orange), causal edges `Hue[0, 1, 0.56]` (dark red), states-graph vertices `Hue[0.62, 0.45, 0.87]` at opacity 0.7 (blue), states-graph edges `Hue[0.75, 0, 0.35]` (gray), branchial edges `Hue[0.89, 0.97, 0.71]`, and the rule-plot grid `GrayLevel[0.85]`. Every kind of object gets one color, and that color is the same in every picture.
- **Games as multiway systems.** "Games and Puzzles as Multicomputational Systems" (2022), https://writings.stephenwolfram.com/2022/06/games-and-puzzles-as-multicomputational-systems/. For 3×3 tic-tac-toe, "the full layered graph—with 6046 states" becomes "a 5478-node graph" once won states are pruned. The essay uses a "move-layered" form, where each layer is one move. It colors subgraphs ("light cones") to show "which player can force a win from that state," and draws branchial graphs per step to show where wins fall in "game state space." It also redraws the same game in "a more symmetrical rendering" or "an alternative layout" whenever that makes structure clearer.

### 5. Production and perception notes from NKS

- "Using color": "what made me decide not to use color in this book were issues of visual perception ... a red element tends to look purple or pink if the elements around it are respectively blue or white ... it is typical for this effect to make all sorts of spurious patterns appear." https://www.wolframscience.com/nks/notes-0-1--using-color/
- "Pictures in the book": all diagrams were made in Mathematica. Placing them without figure numbers "required solving innumerable small geometrical puzzles," which worked because "the Mathematica programs for generating the pictures were almost always general enough that it was straightforward for me to get, say, a picture with a different number of cells or steps." https://www.wolframscience.com/nks/notes-0-1--pictures-in-the-book/
- "Printing": the pictures "often ... contain hundreds of cells per inch, each in effect independently black or white," so the book needed sheet-fed printing on smooth paper. https://www.wolframscience.com/nks/notes-0-1--printing/ and the colophon, https://www.wolframscience.com/nks/colophon/
- "Notation": the main text avoids formal notation, "usually relying instead on diagrammatic pictures"; the notes use Mathematica code as the exact notation. https://www.wolframscience.com/nks/notes-0-1--notation/ This is the same split MAPS makes between the diagram and the `.maps` text.

### 6. Method (pp. 108-113)

https://www.wolframscience.com/nks/p111--how-the-discoveries-in-this-chapter-were-made/ and the pages either side of it.

- "It is usually much better ... to do a mindless search of a large number of possible cases than to do a carefully crafted search of a smaller number."
- "I have always found it much better to look explicitly at the actual behavior of systems, than to work from some kind of summary."
- "if one manages to present this data in the form of pictures then it effectively becomes possible to analyze very quickly just with one's eyes."
- Rule 30 was missed at first. Wolfram looked only at the 32 symmetric rules, and his 1983 picture of rule 30 "showed only 20 steps." He saw what it meant only after he "generated some straightforward pages of pictures of all 256 elementary rules evolving from simple initial conditions" (p. 112).
- Mobile automata led him to a compressed view, showing only the steps where the active cell reaches new ground. That view hid interesting cases from his automated search until he changed the search to account for it (pp. 112-113). The lesson: a summary view can hide exactly the behavior you are looking for.

- **Wolfram Media's "Technical Production Notes"** for NKS turned up in search, but I did not open it.
- **That published Physics Project images used exactly the SetReplace values.** I read the style table at the SetReplace commit above. The Function Repository version may differ, and I did not render anything to compare.
- **Visual claims about images.** I inspected NKS page images for pp. 53, 55, 79, 199, 205, and 209 only. I did not inspect the Physics Project or "Games and Puzzles" images; for those I worked from text and code alone. Three readings are my own inferences from images, not statements by Wolfram: that the 8-per-row grid lines columns up by low bits, that cell size stays fixed while frame width varies, and that node positions persist across the p. 209 stages.
- **Why 8 per row.** Neither the page nor the notes say. It may simply fit the page.
- **The full p. 490 sentence** was cut off in my text extract.

## Open questions for MAPS (not decisions)

- Should a MAPS design have a canonical identity (up to renaming and isomorphism) that ignores `at x y`, with the authored layout treated as presentation?
- What is MAPS's "fixed protocol" for side-by-side pictures: the layered reachability graph from the initial marking, the net drawn in a uniform algorithmic layout, or both?
- What is the family key for a "signature": counts of states, seat verbs, and world verbs per arc kind?
- Should seat colors become a fixed palette with fixed meanings, and should anything that needs comparing be drawn so it still reads in grayscale?
